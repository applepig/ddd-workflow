# Skill: DDD:plan

## 說明
前置規劃階段。當需求還不明確、無法直接寫 spec 時，先用這個階段釘清方向。

## 觸發指令
`/DDD:plan <需求簡述>`

## 輸入
使用者提供的初步需求描述，可以很模糊。

## 執行步驟

1. **建立文件包**
   - 確認或建立 `docs/<編號>-<名稱>/` 資料夾
   - 建立 `plan.md`

2. **需求釐清**
   - 用 AskUserQuestion 向使用者確認以下問題：
     - 這個功能要解決什麼問題？
     - 預期的使用者是誰？
     - 有沒有已知的限制或偏好？
   - 根據回答整理出初步方向

3. **撰寫 plan.md**
   - **背景**：為什麼要做這個功能
   - **目標**：粗略的目標描述（不需要像 spec 那麼精確）
   - **可能的方向**：列出 2~3 個可行方案
   - **待釐清事項**：需要進一步調研的問題
   - **下一步**：建議接下來是進入 research 還是直接寫 spec

4. **交付**
   - 將 plan.md 內容呈現給使用者確認
   - 根據回饋調整，直到使用者同意方向

## 產出
`docs/<編號>-<名稱>/plan.md`

## 結束條件
使用者確認方向後，建議下一步：
- 需要技術調研 → 引導使用者執行 `/DDD:research`
- 方向已明確 → 引導使用者執行 `/DDD:spec`
